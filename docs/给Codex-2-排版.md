这是一份参赛作品的技术文档，读者是评审专家。文案已经写好，
配图也已完成（`docs/build/` 与 `docs/screenshots/`），需要你完成排版并输出 DOCX 与 PDF。

## 任务二：排版成稿


### 输入

- `docs/技术文档-正文.md` —— 全部文案
- 你绘制的配图

正文里用 `> **【插入图 N】标题**` 标出图片位置，`> 图注：...` 给出图注。

### 输出

- `docs/成都猫狗小院-技术文档.docx`
- `docs/成都猫狗小院-技术文档.pdf`

### 排版规格

**页面**
- A4，页边距上下 2.5cm、左右 2.6cm
- 正文行距 **1.3 倍**，段后 0.3 行
- 页脚居中显示页码
- 一级标题**通常**另起一页，但**如果上一节结束时该页已排不满三分之一，
  就紧接排布**，不要留大片空白

**这一组参数是试排出来的。** 按最终规格把整份正文排过一遍并数了页数：
行距 1.5 时 40 页，1.35 时 36 页，**1.3 时 30 页**，刚好达标。
图片宽度从占满版心收到 60% 也能省下约一页。

**字体**
- 正文：微软雅黑 10.5pt
- 一级标题：微软雅黑加粗 18pt
- 二级标题：微软雅黑加粗 14pt
- 三级标题：微软雅黑加粗 12pt
- 代码与英文技术名词：Consolas 9pt
- **中文必须同时设置 `w:eastAsia` 字体**，只设 `font.name` 会导致中文回退

**表格**
- 三线表风格（顶线、表头下线、底线），不要满格网格
- 表头 9.5pt 加粗，单元格内容 9pt，行距单倍，段前段后为 0
- 表格宽度不超过版心，每个表格上方给出表号与表名

**图片**
- 居中，宽度**占版心 60%**，保持原始宽高比
- 不要占满版心——占满会让图片变高，11 张图累积起来多占近两页
- 图下方给图注，格式「图 N　名称」，9pt 居中
- 界面截图（图 8 至图 11）**先裁掉多余空白再排版**，只保留要展示的区域，
  不要整屏缩放；裁切后按 60% 版心宽度排入

**封面与目录**
- 封面顶部放一张横幅比例的小院合影，**不编号**、不加图注：
  用 `assets/team-photo.jpg`（250KB，1400×935，已做过暖色调处理）
- 封面包含：文档标题、副标题（赛事名称与赛项主题）、线上地址、日期
- 封面后插入目录页，列出各章节与页码

### PDF 输出要求

**必须嵌入字体。** 这是硬要求，不是可选项。

评委的电脑上不一定装了微软雅黑。字体没嵌入时，阅读器会替换成别的字体，
**行距、字距、分页全部会变**，你精心调好的版面在评委那里是另一个样子。

导出后**必须验证**：在 PDF 文件里搜索 `/FontFile` 记录。

```bash
# 能搜到 /FontFile 说明字体已嵌入；一个都没有就是没嵌
grep -c /FontFile 成都猫狗小院-技术文档.pdf
```

如果确实没有嵌入，改用 LibreOffice 的 PDF 导出选项强制嵌入标准字体，
或用其他能嵌入字体的转换方案。**不要交付没有嵌入字体的 PDF。**

另外确认：中文没有变成方框或乱码，表格线没有错位，图片没有变形。

### 硬约束

**PDF 页数不得超过 30 页。** 赛事硬性要求，超了会影响评审。

页数**试排过，不是估计**：按 A4、页边距 2.5/2.6cm、微软雅黑 10.5pt
试排整份正文，结果是 **40 页**，其中约 4 页是"每章强制另起一页"
造成的章末空白。据此已把行距收紧到 1.3、图片收到版心 60%、
表格字号降到 9pt，并要求短章节紧接排布，**试排结果为 30 页，刚好达标**。

正文约 2.1 万字，配 11 张图与十余张表格。**排版后必须以实测页数为准**，
不要沿用这里的推算。

如果实测仍然超过 30 页，按以下顺序处理：

1. 检查是否还有章末大片空白（短章节应紧接排布）
2. 图片宽度从 60% 降到 50%
3. 行距从 1.3 降到 1.2
4. 表格行距与字号再收一档

**以上都调整过仍然超标，报告委托方，不要自行删减正文内容。**
正文里每一段都是有信息量的，删哪里应当由写作方判断，
请把超出的页数和挤不下的章节位置报告上来。

**不得改动事实。** 可以润色语句、修正错别字、调整段落顺序，
但**不得新增任何技术细节**——正文里每一处技术描述都来自真实实现，
你没有项目上下文，凭想象补充的内容会是错的。
发现遗漏或前后矛盾，**标记出来交给写作方**，不要自行填补。

**不得出现真实密钥。** 任何形式的 API Key、机器人地址、密码都不得写入文档。

### 验收

自行检查并报告结果：

1. 转 PDF，读取页数，确认不超过 30 页
2. 在 PDF 里搜索 `/FontFile`，确认字体已嵌入
3. 逐页渲染成图片，检查：文字是否溢出表格或图片、是否有标题孤行、
   配图是否清晰且图注对得上、页码是否连续
4. 检查目录中的章节与实际一致
5. 报告最终页数与文件路径

**发现问题就修，修完重新渲染确认。不要只跑一遍就交付。**

## 参考：本机可用的工具链

如果环境与本机一致，DOCX 转 PDF 与逐页渲染可用内置 LibreOffice Kit：

```bash
node <libreoffice-kit>/lib/cli.js convert --input 文档.docx --output 文档.pdf
node <libreoffice-kit>/lib/cli.js render --input 文档.docx --output-dir preview --pages 1,2,3 --dpi 110
```

`render` 的返回里有 `pageCount`、每页图片路径与缺失字体信息。

Word 文档生成可用 `python-docx`。绘图工具由你自行选择。
如果环境不同，用你手上可用的方案，能达到同样效果即可。
